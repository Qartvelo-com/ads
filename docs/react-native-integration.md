# React Native integration (`@qartvelo/react-native-ads`)

`@qartvelo/react-native-ads` brings Qartvelo Ads banner, interstitial and rewarded ads to React Native apps on
Android. It is a thin bridge: everything that decides which ad is shown (campaign selection,
timeouts, AdMob fallback, de-duplication of requests, the reward-once guarantee) runs in the native
Kotlin Qartvelo Ads SDK described in [android-integration.md](android-integration.md). The JavaScript layer
only validates arguments, converts results into typed objects and forwards events.

- New Architecture: a TurboModule (`NativeQartveloAds`) and a Fabric component (`QartveloAdsBannerView`), both
  generated by React Native codegen and autolinked.
- Android only for now. On iOS (and web) the API rejects with `unsupported_platform`, listeners and
  `setPrivacy`/`setLogLevel` are no-ops, `<QartveloAdsBanner />` renders nothing and
  `QartveloAds.isSupported()` returns `false`. The TypeScript surface is platform-neutral so an iOS SDK
  can be added without API changes.
- Tested with React Native 0.87.1 (React 19.2), Android Gradle Plugin 9.2, Gradle 9.4, JDK 17.

## Requirements

| | |
|---|---|
| React Native | 0.79 or newer with the New Architecture enabled (`newArchEnabled=true`, the default) |
| Android | minSdk 23 (React Native itself needs 24), compileSdk 35 or newer |
| Native SDK | `qartvelo-ads-core` 0.2.0 from JitPack, optionally `qartvelo-ads-admob` (resolved automatically) |
| Build JDK | 17 |

## 1. Install

```sh
npm install @qartvelo/react-native-ads
```

Inside this repository the example app uses the local package instead:
`"@qartvelo/react-native-ads": "file:../packages/react-native-qartvelo-ads"`.

The plugin pulls the native SDK from JitPack
(`com.github.Qartvelo-com.qartvelo-ads-sdk:qartvelo-ads-core:0.2.0`); no account or token is needed.

## 2. Android Gradle configuration

### Repository

The app's runtime classpath must be able to resolve the SDK, so add JitPack to every project in
`android/build.gradle`:

```groovy
// android/build.gradle
allprojects {
    repositories {
        maven {
            url "https://jitpack.io"
            content { includeGroup("com.github.Qartvelo-com.qartvelo-ads-sdk") }
        }
    }
}
```

To use GitHub Packages or a local SDK build instead, set `QartveloAds_sdkGroup=com.qartvelo` in
`android/gradle.properties` and add that repository (`mavenLocal()` after
`./gradlew publishToMavenLocal` in the SDK's `android/` directory).

### AdMob fallback (optional)

Without further configuration the plugin depends on `qartvelo-ads-core` only, and a Qartvelo Ads no-fill simply
reports "no ad". To let Qartvelo Ads fall back to your own AdMob ad units, enable the AdMob adapter in
`android/gradle.properties`:

```properties
# android/gradle.properties
QartveloAds_admobEnabled=true
# Optional: pin a different SDK version (default 0.2.0)
# QartveloAds_sdkVersion=0.2.0
```

`qartvelo-ads-admob` brings in `com.google.android.gms:play-services-ads` (25.4.0). Google's SDK requires
your AdMob App ID in `android/app/src/main/AndroidManifest.xml`, or the app crashes at startup:

```xml
<application ...>
  <meta-data
    android:name="com.google.android.gms.ads.APPLICATION_ID"
    android:value="ca-app-pub-xxxxxxxxxxxxxxxx~yyyyyyyyyy" />
</application>
```

For development you can use Google's sample App ID `ca-app-pub-3940256099942544~3347511713`. The
AdMob units per placement come from the Qartvelo Ads dashboard (or `admobAdUnits`, below). See
[admob-fallback.md](admob-fallback.md) for how the fallback decides.

### Local backend over HTTP (debug only)

A local backend such as `http://10.0.2.2:8000/` (the host machine as seen from the Android emulator)
needs cleartext HTTP in debug builds. Add a debug-only network security config:

```xml
<!-- android/app/src/debug/res/xml/network_security_config.xml -->
<network-security-config>
  <domain-config cleartextTrafficPermitted="true">
    <domain includeSubdomains="false">10.0.2.2</domain>
    <domain includeSubdomains="false">localhost</domain>
  </domain-config>
</network-security-config>
```

```xml
<!-- android/app/src/debug/AndroidManifest.xml -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">
  <application
      android:networkSecurityConfig="@xml/network_security_config"
      tools:ignore="UnusedAttribute" />
</manifest>
```

`localhost` keeps Metro working on physical devices through `adb reverse tcp:8081 tcp:8081`.
Release builds must use an HTTPS base URL.

Rebuild the app after installing or upgrading the package (`npx react-native run-android`): the
TurboModule and the banner component are compiled into the app.

## 3. Initialize

Call `initialize` once, as early as possible (for example in your root component). Use the app key
from the publisher dashboard; the server-side SDK secret never goes into the app.

```tsx
import { QartveloAds, isQartveloAdsError } from '@qartvelo/react-native-ads';

useEffect(() => {
  QartveloAds.initialize({
    appKey: 'app_xxxxxxxxxxxxxxxxxxxxxxxx',
    baseUrl: 'https://api.your-ourads-host.com/',
    requestTimeoutMs: 800,
    testMode: __DEV__,
  }).catch((error) => {
    // The SDK keeps working on its cached configuration and AdMob fallback.
    if (isQartveloAdsError(error)) console.warn(error.code, error.message);
  });
}, []);
```

| Option | Type | Default | Meaning |
|---|---|---|---|
| `appKey` | `string` | required | Publisher app key (`app_...`). |
| `baseUrl` | `string` | SDK default | Qartvelo Ads API base URL (`http(s)://.../`). |
| `requestTimeoutMs` | `number` | `800` | Qartvelo Ads request budget before falling back. A per-placement value from the server wins. |
| `testMode` | `boolean` | `false` | Built-in test ads only, nothing billed; AdMob uses Google's test units. |
| `testForceNoFill` | `boolean` | `false` | In test mode, Qartvelo Ads answers "no fill" so you can see the AdMob fallback. |
| `admobFallback` | `boolean` | `true` | Allow the AdMob adapter (needs `QartveloAds_admobEnabled=true`). |
| `logLevel` | `'none' \| 'error' \| 'info' \| 'debug'` | `'error'` | Logcat verbosity (tag `QartveloAds`). |
| `admobAdUnits` | `Record<string, string>` | `{}` | Placement code to your AdMob unit id; overrides the dashboard mapping. |

Behaviour worth knowing:

- Initialization is idempotent for the life of the process. Later calls resolve or reject with the
  first result and ignore new options; restart the app to change them (a JS reload is not enough).
- A rejection (`network_error`, `timeout`, `not_initialized` for a rejected app key) does not disable
  ads. Loads still run on the last cached configuration and can fall back to AdMob.
- Loads issued while initialization is still running wait for it.
- `QartveloAds.isInitialized()` resolves `true` once the first attempt has finished.

## 4. Banner

```tsx
import { QartveloAdsBanner } from '@qartvelo/react-native-ads';

<QartveloAdsBanner
  placementId="home_banner"
  style={{ width: '100%' }}
  onLoaded={(e) => console.log('banner from', e.source)}
  onLoadFailed={(e) => console.log(e.error.code)}
/>
```

- The banner is collapsed (height 0) until an ad is rendered, then takes the creative's height
  (Qartvelo Ads creatives keep their aspect ratio within the width; AdMob uses an anchored adaptive
  size). Set an explicit `height` in `style` to reserve space instead.
- Props: `placementId` (required), `style`, `onLoaded`, `onLoadFailed`, `onShown`, `onImpression`,
  `onClicked`, `onFallbackStarted`, `onNoAdAvailable`, `onSizeChange`. Each callback receives the
  same payload as the corresponding global event (see Events).
- Re-renders never reach the SDK: the native props are only `placementId`, the style and two event
  handlers with a stable identity. Changing `placementId` loads the new placement.
- Remounting (navigation, list recycling, toggling the component) does not request a new ad: the
  SDK keeps one banner per placement and the new view re-attaches to it. The component's
  `onLoaded` fires again for the new view; global listeners do not get a second `loaded`.
- Refresh follows the placement's `banner_refresh_seconds` (minimum 30 s) and pauses while the
  banner is off screen or the app is in the background.
- One visible banner per placement code at a time. Use different placement codes for banners that
  are on screen simultaneously.
- A banner mounted before `initialize()` waits and loads as soon as initialization starts.

## 5. Interstitial

```tsx
try {
  const info = await QartveloAds.loadInterstitial('game_end'); // { placementId, format, source, campaignId?, creativeId? }
  // ... later, at a natural break:
  const result = await QartveloAds.showInterstitial('game_end'); // resolves on dismiss
  if (!result.shown) {
    // nothing was ready; continue the game
  }
} catch (error) {
  // QartveloAdsError: no_fill, timeout, network_error, already_showing, ...
}
```

- `loadInterstitial` resolves with the source that will be shown (`ourads`, or `admob` after a
  fallback) and rejects when no source has an ad. Concurrent loads of one placement share a single
  request.
- `showInterstitial` resolves `{ shown: true, source }` after the ad is dismissed, or
  `{ shown: false }` immediately when nothing was ready. It rejects with `already_showing` while
  another full-screen ad is visible and with `show_failed` if the ad could not be displayed.
- `QartveloAds.isInterstitialReady(placementId)` resolves whether a show would display an ad now.
- An Qartvelo Ads ad is valid for 30 minutes after loading; an expired ad is never shown.

## 6. Rewarded

```tsx
await QartveloAds.loadRewarded('reward_coins');
const result = await QartveloAds.showRewarded('reward_coins');
if (result.rewarded) {
  grantCoins(result.reward!.amount); // { type, amount }
}
```

- `result.rewarded` is `true` exactly once per show and only after the SDK confirmed completion,
  whether Qartvelo Ads or the AdMob fallback served the ad. A skipped ad resolves
  `{ shown: true, rewarded: false }`.
- Qartvelo Ads rewards are `{ type: 'reward', amount: 1 }`; AdMob rewards carry the type and amount
  configured for your AdMob unit.
- Grant the reward from the promise result or from the `rewarded` event, not from both.
- `QartveloAds.isRewardedReady(placementId)` works like the interstitial variant.

## 7. Events

`addListener` observes SDK events of every placement and format, banners included. Always remove the
subscription when the screen goes away:

```tsx
useEffect(() => {
  const subscriptions = [
    QartveloAds.addListener('fallbackStarted', (e) => log(`fallback ${e.placementId}: ${e.reason}`)),
    QartveloAds.addListener('rewarded', (e) => log(`reward ${e.reward.amount} ${e.reward.type}`)),
  ];
  return () => subscriptions.forEach((s) => s.remove());
}, []);
```

| Event | When | Extra fields |
|---|---|---|
| `loaded` | An ad is ready (Qartvelo Ads, or AdMob after a fallback) | `source`, `campaignId?`, `creativeId?` |
| `loadFailed` | A load or show failed | `error: { code, message }` (`format` may be missing for a placement this app never used) |
| `shown` | The ad is on screen | `source`, ids |
| `impression` | The impression was counted | `source`, ids |
| `clicked` | The user tapped the ad (at most once per ad) | `source`, ids |
| `dismissed` | A full-screen ad was closed | `source`, ids |
| `rewarded` | Completion confirmed for a rewarded ad | `source`, `reward: { type, amount }` |
| `fallbackStarted` | Qartvelo Ads could not serve; AdMob is being tried | `reason`: `no_fill`, `timeout`, `error`, `creative_failed`, `disabled` |
| `noAdAvailable` | No source has an ad | |

Every payload has `type`, `placementId` and `format` (`banner`, `interstitial` or `rewarded`).
`source` is `ourads` or `admob`; `campaignId` and `creativeId` are set only for Qartvelo Ads ads. Each
`addListener` call is an independent subscription; `remove()` is safe to call twice, and
`QartveloAds.removeAllListeners(type?)` clears listeners in bulk. The native event stream is open only
while at least one listener exists.

## 8. Errors

Every promise rejects with an `QartveloAdsError` (`error.code`, `error.message`, and `error.placementId`
for placement calls). Use `isQartveloAdsError(error)` to narrow.

| Code | Meaning |
|---|---|
| `not_initialized` | `initialize()` was not called, or the backend rejected the app key. |
| `invalid_placement` | Unknown placement code, or a placement used with the wrong format. |
| `no_fill` | Neither Qartvelo Ads nor the fallback had an ad. |
| `timeout` / `network_error` | The Qartvelo Ads backend was slow or unreachable (and no fallback was available). |
| `creative_failed` | The Qartvelo Ads creative could not be downloaded or decoded. |
| `already_showing` | Another full-screen ad is on screen. |
| `show_failed` | The ad could not be displayed (for example no foreground Activity). |
| `ad_expired`, `internal_error` | Reserved by the SDK / unexpected native failure. |
| `invalid_argument` | A JavaScript argument was rejected before reaching native code. |
| `unsupported_platform` | Called on a platform without the Qartvelo Ads SDK (iOS, web). |
| `module_unavailable` | The native module is missing: rebuild the Android app. |

## 9. Privacy

Qartvelo Ads targets contextually and creates no persistent user identifier. Pass the privacy signals your
app collected; anything you omit stays "unknown" and consent is never assumed:

```ts
QartveloAds.setPrivacy({ consentGiven: false, childDirected: true, underAgeOfConsent: undefined });
QartveloAds.setLogLevel('debug'); // runtime log verbosity
```

The signals are forwarded to the AdMob fallback, where they only add restrictions (non-personalized
ads, child or under-age treatment). Collect consent for Google ads yourself (for example with
Google's User Messaging Platform); Qartvelo Ads never shows a consent form. See [privacy.md](privacy.md).

## 10. Testing

### With test ads

- `testMode: true` serves the backend's built-in test creatives (nothing is billed) and makes the
  AdMob adapter use Google's public test units.
- `testMode: true, testForceNoFill: true` makes Qartvelo Ads answer "no fill", so every load shows
  `fallbackStarted` followed by an AdMob test ad. The reward from Google's rewarded test unit is
  10 coins.

### Example app

`react-native/example` (package `com.qartvelo.rnexample`) demonstrates every format, the event log,
test mode and forced no-fill. With the backend seeded (`php artisan migrate:fresh --seed`) and
running on port 8000:

```sh
cd android && ./gradlew publishToMavenLocal              # SDK into ~/.m2 (once)
cd react-native/packages/react-native-qartvelo-ads && npm install && npm run build
cd react-native/example && npm install
npx react-native start                                    # Metro
npx react-native run-android                              # or: cd android && ./gradlew assembleDebug
```

Tap Initialize (app key `app_demo_rn_example_0001`, base URL `http://10.0.2.2:8000/`, both editable
before initializing), then load and show each format. Turn on "Force Qartvelo Ads no-fill" before
initializing to watch the AdMob fallback. "Unmount banner" / "Re-render screen" show that the banner
is not requested again.

### Package checks

```sh
cd react-native/packages/react-native-qartvelo-ads
npm test            # Jest with the native module mocked
npm run typecheck   # tsc
npm run lint        # ESLint + Prettier
cd ../../example/android && ./gradlew :ourads_react-native:testDebugUnitTest   # Kotlin bridge tests
```

In your own Jest tests, mock the package, for example
`jest.mock('@qartvelo/react-native-ads', () => ({ QartveloAds: { initialize: jest.fn(), ... }, QartveloAdsBanner: () => null }))`.
Without a mock it behaves as on iOS (the Jest preset reports iOS): promises reject with
`unsupported_platform` and the banner renders nothing.

## 11. Troubleshooting

| Symptom | Fix |
|---|---|
| `Could not find ...qartvelo-ads-core:0.2.0` | Add JitPack to `allprojects.repositories` (section 2). With `QartveloAds_sdkGroup=com.qartvelo`, run `./gradlew publishToMavenLocal` in the SDK project and add `mavenLocal()`. |
| App crashes at start with "The Google Mobile Ads SDK was initialized incorrectly" | `QartveloAds_admobEnabled=true` without the AdMob `APPLICATION_ID` meta-data. Add it, or disable the adapter. |
| Promises reject with `module_unavailable` | The app binary predates the package. Rebuild with `npx react-native run-android`. |
| Promises reject with `unsupported_platform` | Running on iOS or web; only Android has an SDK today. |
| `initialize` rejects with `network_error` on the emulator | Use `http://10.0.2.2:<port>/`, not `localhost`, and allow cleartext for it in debug (section 2). |
| `initialize` rejects with `not_initialized` | The backend rejected the app key: check the key, that the package name matches the app's applicationId, and that the app is approved (or use `testMode`). |
| Options seem ignored | Initialization happens once per process; force-stop and restart the app after changing options. |
| Every load ends with `fallbackStarted` reason `timeout` | The backend answered after `requestTimeoutMs`. Expected for a cold debug backend; raise the timeout in the dashboard or the option while testing. |
| `fallbackStarted` but no AdMob ad | `QartveloAds_admobEnabled` is not set, `admobFallback` is false, the placement's fallback is `none`, or no AdMob unit is configured for it. |
| Banner stays empty | Check `onLoadFailed`; make sure the component has a width (it defaults to `100%`) and that only one banner per placement code is visible. |
| Two copies of React in Metro (local package) | Point Metro's `watchFolders` at the package and block its `node_modules/react(-native)`, as in `react-native/example/metro.config.js`. |
